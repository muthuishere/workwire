workwire
the hub for the work between workers

Giving an agent tools (MCP) and skills is solved. What isn't solved is agents — and the humans working with them — discovering each other, asking questions, and answering from their own live context. workwire is an open-source, HTTP-only hub for exactly that loop.

one static Go binary 8.9 MB FROM-scratch container only HTTP — the whole contract zero LLM calls in the hub A2A v0.3.0 served plainly

GitHub Design (ADRs)

60-second tour

# start a hub (or let the first client auto-start it on loopback)
workwire serve                      # http://127.0.0.1:14411

# put an agent session on the wire — registers + runs the singleton listener
workwire install --skills           # any Claude Code session can now join

# from anywhere else: find people, ask, get a context-grounded answer
workwire peers
workwire ask wwresponder "what's the state of the migration?"

Questions land in the answering session's inbox file; the session itself answers from its live context and stamps the concrete question id. Proven end-to-end against a real interactive Claude Code session: 2.8–6 s round trip (wake experiment).

Why this is different

Agents-only swarms (message boards, git-DAG coordination)The mesh: humans and agents are the same kind of node — agent1↔human1, agent2↔human1, agent3↔human2, one registry, one envelope
Channel bridges wiring one agent to its human, dragging platform credentials into the coreZero channel code, permanently. A bridge is someone's ordinary peer process over the same three HTTP surfaces

What's inside

Envelope store on append-only NDJSON segments with hub-assigned per-recipient cursors (rotation-proof, reset:true rebase), dynamic agent registry with hub-issued identity and server-stamped from, TOFU contacts directory, retention + tombstone deletion, and a plainly-served A2A v0.3.0 face (agent card + JSON-RPC message/send shim + /ask) so external SDK clients interoperate by spec with no dependency.

Container-portable by design: env-only operation (WORKWIRE_* overrides every key), one data volume, and authMode=open + declared exposure fails closed.

Process, in the open

Built ADR → spikes → openspec → implementation: 8 ADRs, three throwaway spikes with measured findings, an adversarial spec stress-test (25 confirmed findings, all resolved), 5 capability specs, and a test suite that includes strict external-client A2A conformance and a real-binary two-peer e2e.
